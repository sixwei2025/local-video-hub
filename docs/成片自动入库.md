# 成片自动入库（桌面产线 → 视频中心「待确认」）

> 六伟定（2026-10-26）：成片要在视频中心看，不要在桌面文件夹里翻。自动入库只到「待确认」；过他确认后才标待发布。禁止已发片二次重发。

## 两条进站路径（差别）

| | 文件系统扫描（网站） | `hub submit`（本工具走这条） |
|---|---|---|
| 入口 | `app.scan()` 扫 `output_dirs` 白名单 | `hub.py new` + `hub.py submit` |
| 建卡 | `ensure_works` 常无标题 → 易出「待确认」空卡 | bot 作品，带标题/封面/简介/话题 |
| 状态 | 多为无元数据的 confirm | 核对通过 → **待确认** |
| 用途 | 浏览磁盘成片 | 正式交片、发布官后续接单 |

`config.scan_roots` 已收紧为**仅存在的桌面产线文件夹**（与 `output_dirs` 一致）。`hub_lib.under_roots` 据此校验：成片必须落在这些目录内才能 submit。

## 产线目录（当前）

见 `config.json` → `output_dirs`。常见：

- `~/Desktop/心理学科普`
- `~/Desktop/口播成片`

## 自动补扫脚本

```bash
cd ~/video-hub
.venv/bin/python tools/sync_desktop_finals.py --dry-run --days 7
.venv/bin/python tools/sync_desktop_finals.py --days 7 --limit 8
```

行为摘要：

1. 只扫 `output_dirs` 里存在的目录中的 mp4/mov/m4v  
2. 跳过文件名/路径含：小样、样片、dryrun、probe、test、测试…  
3. 同目录同选题多版本：有无版本号最终版则丢旧 `vN`；否则只留最高 `vN`  
4. 绝对路径已在 `assets(kind=video)` 或 `works.selected_path` → 跳过  
5. 同选题（标题规范化）已 published 或已有 `selected_path` → 跳过  
6. 可选跳过时长 &lt; 8s（`--min-duration 0` 关闭）  
7. 映射 line/bot/topics（`rules` / `style_rules` / `bot_registry` / `publish_defaults`）  
8. 封面：优先同名/「封面」图（偏好竖 3x4），否则 ffmpeg 抽首帧裁 3:4  
9. `hub new` → `hub submit … --desc "（简介由发布官填写）"` → 待确认  
10. 默认每轮最多 `--limit 8`；stdout 一行 JSON  

## 操盘手硬要求

成片落盘到产线文件夹后，**必须**走 `hub submit` 进视频中心待确认（见 `Grokbot提交规范.md`）。本脚本只是漏交时的兜底，不是正规交片替代。

## 不做

- 不改「待发布」、不发任何平台  
- 不删用户文件（hub 去重把旧版进废纸篓是自带行为）  
- 不清理历史无标题垃圾卡（需另开清理任务）
